# 扫雷 AI（Windows 高级局 30×16）

用 **UIA 无障碍接口**读盘 + **纯逻辑求解**决策 + **UIA/鼠标混合**执行的 Windows 扫雷自动化。
单步约 **100 ms**，能完整自动通关一局；带深色 GUI 控制台，可打包成单文件 exe 迁移到任何 Windows 电脑。

## 特性

- **感知**：走 Windows UIA（每个格子是 `ButtonControl`，Name 里自带语义），识别准确率 100%，不用模板匹配或颜色阈值
- **决策**：确定性规则 + 子集差分 + 按约束连通分量做概率枚举，全程 < 2 ms
- **执行**：开格走 UIA `InvokePattern`（不碰鼠标）；插旗 / chord 走鼠标（UIA 没有对应通道）
- **速度**：单步 ~100 ms。三层读取收缩——边界格 → 焦点九宫格 → 读到空白格才按需展开；chord 批量连点，一次读盘打多个
- **录屏**：`录屏.bat` 用 ffmpeg 抓窗口，60 fps，产出可直接拖进度条的 MP4
- **GUI**：tkinter 深色控制台，实时指标 + 彩色日志 + 急停
- **打包**：`扫雷AI.exe` 单文件（自带扫雷程序），拷到别的电脑就能跑

## 快速开始

```bash
python agent.py --dry          # 只算不点，先看决策对不对
python agent.py --loop 5       # 实点，最多 5 局（输了自动重开）

python 扫雷控制台.bat           # 双击这个开 GUI 控制台
```

## 实测数据

| 项目 | 数值 |
|---|---|
| **单步耗时** | **~100 ms**（click ~65 + read ~30 + 等待/决策 ~5） |
| 一局（230~250 步） | **~24 s** |
| UIA 枚举 480 格 | 8 s（开局一次；**每次开新局还要再来一次**，见下） |
| solver 全套 | < 2 ms |
| 离线模拟胜率 | 初级 82.5% / **高级 26.7%** |
| 连打 3 局实测 | 98 / 99 / 109 ms 每步（246 步胜、233 步胜、195 步负） |

> 新局开始后 UIA 元素引用会失效（`CurrentName` 一直返回上一局的旧数据），
> 所以两局之间必须重新枚举一次（8 s）。不这么做的话第二局必挂——插旗校验读到旧名字，
> 判定"没插上"后补标反而把旗取消了，最后触发熔断。

## 录屏

```bash
python record.py                # 录到运行 停录.bat 或按 Ctrl+C
python record.py --seconds 30   # 只录 30 秒
python record.py --fps 30       # 改帧率
```

或双击 `录屏.bat` / `停录.bat`。产出在 `record/`。

**停止方式决定文件能不能用**——这是 `record.py` 存在的主要理由：

| 停止方式 | 结果 |
|---|---|
| 送 `q` 让 ffmpeg 自己收尾 | ✓ 全片解码零错误 |
| `taskkill /f` 强杀 | ✗ 最后一个分片截断，解码报 `Invalid NAL unit size` |

所以别直接 kill ffmpeg；`停录.bat` 只是建一个 `record\STOP` 标志，由 `record.py`
转成 `q` 送进去。另：抓取按窗口标题（`title=扫雷`），跟着窗口走，也不受 DPI 缩放影响。

## 说明

高级局（30×16 / 99 雷）存在约 5 次"信息不足必须猜"的位置，胜率上限约 **26.7%**——
这是扫雷本身的数学限制，不是求解器的问题。程序在无确定步时会停下（stuck），不盲目乱点。
